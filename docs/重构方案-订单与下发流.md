# 订单流 + 下发流重构方案

> 状态：待实现。2026-07-12 真机实测后整理，在本机（Mac）上探查确认，将在另一台机器上实施。
> 配套：[打印农场-实施方案.md](打印农场-实施方案.md)、[真机接入与部署指南.md](真机接入与部署指南.md)。

## Context（为什么做）

实测真机时发现下单/下发流程的产品缺口：

1. 客户下单要**手填 material**（必填），但 gcode.3mf 里其实有材料/颜色信息，手填可能和 gcode 冲突，计费规则未定义。
2. admin 下发要**手填 bambuddy_printer_id**（数字），无打印机选择界面。
3. 下发 `add_to_queue` **没传 ams_mapping**，Bambuddy 不知道用哪个 AMS 料盘（队列项 ams_mapping=null）。
4. 打印机没所需材料时**无校验**，可能打错料。

### 决策（已拍板）

- 客户**不手填材料**，gcode 是唯一真相。
- `.gcode.3mf` 走全自动（解析→预览→确认→下单）；`.3mf` 模型走 admin 手动切片 + **手工费 surcharge**，不做后台自动切片。
- AMS 不匹配时**展示 gcode 期望料盘 vs 当前 AMS 料盘对比**，admin 手动选替代料盘覆盖下发。
- 计费按 gcode 材料（.3mf 路径按切片后 gcode 材料 + 手工费）。

### 探查已确认的事实

- gcode.3mf 的 `Metadata/slice_info.config` 有 `<filament type="PLA" color="#00AE42" used_g="36.56" tray_info_idx="GFA00"/>` + `<nozzle extruder_id="1"/>`——材料/颜色/克重/料盘映射全可解析。
- Bambuddy `add_to_queue` 接受 `ams_mapping`（array[int]，下标=extruder，值=tray id）、`plate_id`（非现在的 `plate`）。
- 打印机实际料盘在 `printer.status_detail.ams[*].tray[*]`（tray_type/tray_color/tray_sub_brands/remain/state），`/admin/printers` 已返回全量。

## Phase 1：gcode_parser 扩展（解析多色 + AMS 映射）

`backend/services/gcode_parser.py`：

- 改 `_parse_slice_info_xml`：`<filament>` 用 `root.iter("filament")` 收集成 list（不再 setdefault 单值，多色不丢料），每个含 `{id, tray_info_idx, type, color, used_m, used_g}`；`<nozzle>` 同理收成 list `{id, extruder_id, nozzle_diameter}`。
- 返回结构向后兼容：保留 `filament_used_g`（=各 filament used_g 之和）、`print_time_s`；新增 `filaments`/`nozzles`/`plate_index`。
- 新增 `extract_ams_expectation(parsed)`：从 filaments+nozzles 派生 `[{extruder_id, type, color, tray_info_idx, used_g}]`（gcode 期望料盘，AMS 校验用）。
- gcode 注释兜底路径保留（只给 weight/time，无 filaments → AMS 校验降级为"无法校验"）。

测试 `tests/test_pricing.py`：加多色 parse、nozzle 映射、legacy 兼容、extract_ams_expectation 用例。

## Phase 2：PricingService 加手工费

`backend/services/pricing.py`：

- `calc(weight, seconds, material=None, surcharge=False)` + `describe(...)` 加 `surcharge` 参数；surcharge=True 时加 `manual_slice_surcharge` 配置项（固定金额，单位"次"，默认 5）。
- `describe` 返回加 `surcharge` 字段。
- `seed_pricing.py` + `tests/conftest.py` 的 `_PRICING_DEFAULTS` 加 `("manual_slice_surcharge", 5, "global", "手工切片费", "次")`。
- 迁移：新增 alembic 迁移 INSERT 该配置行（或靠 seed 幂等，项目现有模式）。

## Phase 3：订单流重构（preview 接口 + 两条文件路径）

`backend/models.py` PrintOrderModel 加字段：`parsed_filaments`(JSON)、`parsed_nozzles`(JSON)、`is_manual_slice_path`(Bool, default 0)。迁移 ALTER TABLE。

`backend/blueprints/orders.py`：

- **新接口 `POST /orders/preview`**：收 .gcode.3mf → 流式落临时 → 解析 → 返回 `{filaments, material, filament_used_g, print_time_s, quote: PricingService.describe(...)}`，**不落库不冻 credit**，临时文件即删。解析失败返回 422。
- **改 `POST /orders/`**：删 material 必填校验；`.gcode.3mf` → 解析取主材料（used_g 最大的 filament.type）→ `calc(..., surcharge=False)` → status=WAITING_CONFIRM + 存 parsed_filaments/nozzles + is_manual_slice_path=False；`.3mf` → 不解析 → status=QUOTING + is_manual_slice_path=True（无报价，等 admin 切片）。order.material 从 gcode 推导填（展示用）。
- `confirm` 不动（freeze 逻辑复用）。
- `_order_to_dict` 加 parsed_filaments/is_manual_slice_path。

`backend/blueprints/admin.py`：

- 改 `POST /admin/orders/{id}/upload-sliced`：用扩展 parser 解析 → 存 parsed_filaments/nozzles → `calc(..., surcharge=True)`（.3mf 路径加手工费）→ material 从 gcode 推导。返回加 quote 明细。
- `_admin_order_to_dict` 加新字段。

## Phase 4：下发重构（打印机下拉 + AMS 校验 + ams_mapping）

**新文件 `backend/services/ams_matcher.py`**（纯函数，无 DB/IO，可单测）：

- `match_ams(expected_filaments, printer_ams_status) -> {matched, mappings:[{extruder_id, expected, actual_tray_id, actual_tray, match_type(exact/color/type/none), alternatives}], ams_mapping}`
- 匹配优先级：exact（tray_info_idx+type+color 全等）> color（type+color）> type > none。
- 颜色归一化：去 `#`、取前 6 位、大写（gcode `#00AE42` vs AMS `00AE42FF`）。
- 只匹配 state==3 且 remain>0（或 -1 未知）的 tray。
- 全匹配给 `ams_mapping` 数组（下标=extruder_id，值=tray_id）；不全匹配 None。

`backend/bambuddy_adapter.py`：`add_to_queue(archive_id, printer_id, plate_id=1, ams_mapping=None, use_ams=True, ...)`，body 用 `plate_id`（修字段名 bug）+ 透传 ams_mapping。

`backend/tasks/dispatch.py`：`_do_dispatch(order_id, printer_id, ams_mapping=None)` 透传给 add_to_queue；`dispatch_order` task 同步签名。

`backend/models.py` BambuddyJobModel 加 `ams_mapping`(JSON) 列（持久化追溯用）。迁移。

`backend/blueprints/admin.py`：

- **新接口 `POST /admin/orders/{id}/dispatch/preview`**：入参 `{bambuddy_printer_id}` → 读 order.parsed_filaments（无则拉 MinIO 重解析兜底）+ printer.status_detail.ams → 调 `match_ams` → 返回 `{printer, expected_filaments, match_result}`。纯查询不写入。
- **改 `POST /admin/orders/{id}/dispatch`**：入参加 `ams_mapping?`。传了 → 透传（admin 已手选，跳过校验）；没传 → 调 match_ams，matched=True 用其 ams_mapping，matched=False 返回 409 + match_result（提示 admin 手选）。

新文件 `backend/tests/test_ams_matcher.py`：8 个纯函数用例（exact/color/type/none/颜色归一/空 tray 跳过/多色全匹配/多色部分）。`tests/test_dispatch.py` 改 mock 签名 + 加 ams_mapping 持久化用例。

## Phase 5：前端重写

`frontend/customer/src/api/orders.js`：加 `preview(formData)`；`create` 不再带 material。

`frontend/customer/src/views/NewOrderView.vue` 重写：

- 删 material/color/layer_height/nozzle_size 输入框，保留 quantity/customer_note。
- 选文件后按扩展名分支：`.gcode.3mf` → 调 preview → 展示预览卡（材料/颜色色块/克重/时长/报价明细）→ 确认下单；`.3mf` → 提示"需管理员切片，提交后进入待切片状态"→ 提交（带备注）。

`frontend/admin/src/api/admin.js`：加 `dispatchPreview(id, printerId)`；`dispatchOrder(id, printerId, amsMapping)` 加 ams_mapping。

`frontend/admin/src/views/OrdersView.vue` 下发 Dialog 重写：

- printer_id 输入框 → `<select>`（enabled 打印机，label=`{public_name}（bambuddy #{bambuddy_printer_id}）`）。
- 选打印机后调 dispatchPreview → 渲染 AMS 对比表（extruder/期望材料/期望颜色/实际料盘/匹配等级色块/替代料盘下拉）。
- 全匹配直接下发；有 none 且 admin 选了替代料盘后下发；ams_mapping 用 match_result 或 admin 手选。

## Phase 6：测试 + 端到端验证

`cd backend && .venv/bin/python -m pytest tests/ -v` 全绿后，用已起环境端到端：

1. customer 传真实 .gcode.3mf → 看预览卡材料/克重/报价 → 确认下单 → admin 见新单 WAITING_CONFIRM。
2. customer 传 .3mf + 备注 → admin 下载切片 → 上传 .gcode.3mf → 看报价含手工费 → customer 确认。
3. admin 对 READY_TO_PRINT 单开 dispatch → 选打印机 → 看 AMS 对比表 → 全匹配直接下发 → Bambuddy 队列出现任务且 ams_mapping 非 null。
4. 选 AMS 不符的打印机 → 看红色 none 行 → 选替代料盘 → 下发 → 队列 ams_mapping 为 admin 选的值。
5. 回归：现有订单（无 parsed_filaments）dispatch/preview 拉 MinIO 重解析兜底。

## 风险与边界

- **多色无实测样本**：Phase 1 用构造 XML 覆盖；拿到真实多色文件后单独验证 parser。纯函数迭代成本低。
- **迁移 drift**：项目已有 migration 与 model drift（source 列等，实测时用 `db.drop_all()+db.create_all()` 从模型重建绕过）。新列的 ALTER TABLE 迁移在 create_all 的 schema 上仍能 apply（ADD COLUMN 不依赖 baseline）。新迁移正常写。
- **`plate`→`plate_id` 破坏性改名**：仅 `_do_dispatch` + test mock 调用，同步改。Bambuddy 实测只认 plate_id。
- **AMS status 结构变化**：matcher 防御性解析（缺 ams 字段返回 matched=False + 原因），不抛异常。
- **gcode 解析失败**：preview 返 422；create_order 降级为 QUOTING（人工报价），不阻塞下单。
- **手工费收法**：固定金额配置项（非倍率），admin 可在 /admin/pricing 调。

## 执行顺序

Phase 1+2（可并行）→ Phase 3（依赖 1+2）→ Phase 4（4.1 matcher 独立，4.2-4.6 依赖 1+4.1）→ Phase 5（依赖 3+4 接口定稿）→ Phase 6 贯穿。每阶段一个 commit。
