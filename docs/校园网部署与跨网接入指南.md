# BME 3DFarm — 校园网部署与跨网接入指南

> 场景：把后端部署到**校园网上的一台机子**，但打印机（及当前跑 Bambuddy 的开发机）在**接校园网的一台路由器**后面。
> 配套：[真机接入与部署指南.md](真机接入与部署指南.md)（同局域网部署，基础步骤不重复）。

---

## 0. 先搞清一个关键事实

**BME_3DFarm 后端不直连打印机，只通过 HTTP 调 Bambuddy。** Bambuddy 才是那个用 MQTT 连打印机的东西（且必须在打印机能 reach 的局域网里）。

```
校园网机子                      路由器（接校园网）内网
┌──────────────────┐           ┌──────────────────────────┐
│ 后端 5002        │           │ 你的开发机（现跑 Bambuddy）│
│ DB/Redis/MinIO   │  ──HTTP→  │   └─ Bambuddy 8000        │
│ Celery worker/beat│ ←Webhook─ │        └─ MQTT → 打印机    │
│ 前端 nginx       │           │ 打印机 192.168.x.x        │
└──────────────────┘           └──────────────────────────┘
```

所以跨网部署要解决的**唯一一个问题**：**校园网后端 ↔ Bambuddy（在路由器内网）能不能互通。**
打印机的 `192.168.x.x` 局域网地址在这件事里**完全无关**——那是路由器内网私有地址，校园网侧根本不可路由。

---

## 1. 你的"IP 隔离"担心，先 5 分钟测掉

在**校园网那台机子**上跑两个命令（把 IP 换成你的实际值）：

```bash
# ① 能否 reach Bambuddy（如果 Bambuddy 现在跑在你的开发机上）
curl -m 5 http://<开发机的局域网IP>:8000/health

# ② 顺带试打印机 IP（几乎一定不通，仅供诊断）
ping -n 4 <打印机局域网IP>        # Windows
ping -c 4 <打印机局域网IP>        # Linux/Mac
```

**三种结果，对应三条路：**

| 结果 | 含义 | 走哪条 |
|---|---|---|
| ① 通 | 校园机子和开发机在**同一个二层网**（比如校园机其实也接在寝室那台路由器下） | **方案 A**：直接用现有同局域网指南，`BAMBUDDY_BASE_URL=http://<开发机IP>:8000/api/v1`，完事 |
| ① 超时 | 跨网了：校园网侧到不了路由器内网（NAT + 私有地址 + 可能的客户端隔离） | **方案 B（推荐）**：Tailscale 组虚拟网 |
| ② 通但①不通 | 极少见（Bambuddy 没起 / 端口没开） | 检查 Bambuddy 在跑 + 防火墙放行 8000 |

> 你的情况（"打印机接在路由器，路由器接校园网"）大概率是②的跨网场景。**校园网机子 ping 打印机的 192.168 地址基本一定不通**——不是被"隔离"，是私有地址本来就不可跨网路由。所以"用先前局域网地址试试"值得花 5 分钟验证，但心理预期放低。

---

## 2. 方案 A：同局域网（若 ① 通）

直接照 [真机接入与部署指南](真机接入与部署指南.md) 部署全栈到那台机子即可，`.env` 里：
```env
BAMBUDDY_BASE_URL=http://<开发机或Bambuddy所在机IP>:8000/api/v1
```
唯一注意：开发机上的 Bambuddy 要对局域网开放 8000（防火墙放行），校园机子才能调到。本文档以下专注于跨网。

---

## 3. 方案 B（推荐）：Tailscale 组虚拟局域网

**思路**：Bambuddy 留在打印机所在局域网的常开机器上（你的开发机，或更好是一台树莓派/小主机）；校园机子部署后端栈；两端装 [Tailscale](https://tailscale.com/)（免费、WireGuard 内核、能穿透校园 NAT/防火墙，走出站连接），互相得到一个 `100.x.x.x` 的固定虚拟 IP。后端用 Bambuddy 的 Tailscale IP 调它，Bambuddy 用后端的 Tailscale IP 推 Webhook。打印机连接完全不受影响（Bambuddy 仍在打印机同局域网）。

### 3.1 为什么是 Tailscale 而不是端口转发 / frp
- **校园网几乎都禁入站**：你在校园机子上 `nc -l 5002`，校外/路由器侧连不进来。端口转发要求公网 IP，校园机没有。
- **Tailscale 走出站**：两端主动连 Tailscale 的中转（DERP），不依赖入站放行；能直连时自动打洞（P2P），否则中转，都能用。
- **frp/ngrok 也能做**，但需要一台**公网**中转机（你要租云服务器），配置更重。Tailscale 零中转机。

### 3.2 两端装 Tailscale
开发机（Windows，现有）和校园机子（Linux 为主，命令类似）都装，登录**同一个** Tailscale 账号：
```bash
# Windows：官网下载安装包，托盘登录
# Linux（校园机）：
curl -fsSL https://tailscale.com/install.sh | sh
sudo tailscale up
tailscale ip -4        # 记下这台的 100.x.x.x
```
两端各记一个 `100.x.x.x`：
- `BAMBUDY_TS_IP` = 开发机（跑 Bambuddy 那台）的 Tailscale IP
- `BACKEND_TS_IP` = 校园机的 Tailscale IP

验证互通（在校园机上）：`curl http://<BAMBUDY_TS_IP>:8000/health` → 200。

> 如果校园网连 Tailscale 的 DERP 也墙了（极少见，国内偶发），换 [Headscale](https://github.com/juanfont/headscale) 自建 或 frp。

### 3.3 让 Bambuddy 监听 Tailscale IP（开发机上）
默认 Bambuddy Docker 只映射 `127.0.0.1:8000` 或 `0.0.0.0:8000`。校同机调得到即可，但要让**校园机**通过 Tailscale 调到，Bambuddy 必须 listen 在能被 Tailscale 接口的地址。两种做法（任选）：
- **简单**：开发机上 Bambuddy 容器 `ports: "8000:8000"`（0.0.0.0）+ Windows 防火墙放行 8000 给 Tailscale 网卡。Tailscale 流量走 `100.x`，Windows 会走 Tailsucky 虚拟网卡，放行即可。
- **干净**：开发机上也把 Bambuddy 纳入 Tailscale（`tailscale serve` / `tailscale funnel` 内网穿透），不暴露 8000 到 LAN。

验证：校园机 `curl http://<BAMBUDY_TS_IP>:8000/health` → 200。**这一步通了，跨网就稳了。**

### 3.4 校园机部署后端栈

用项目自带 `docker-compose.yml`，但**不启动 bambuddy**（它留在开发机上）：

```bash
git clone <仓库> BME_3DFarm && cd BME_3DFarm
cp backend/.env_example backend/.env
# 编辑 .env（见下）
docker compose up -d mysql redis minio backend worker beat
```

`.env` 关键改动（相对本地开发）：
```env
DB_HOST=mysql            # compose 内服务名（backend 和 mysql 同一 compose 网络）
DB_PORT=3306
DB_NAME=bme_3dfarm
DB_USERNAME=root
DB_PASSWORD=<强随机>
REDIS_URL=redis://redis:6379/0

JWT_SECRET=<python -c "import secrets;print(secrets.token_hex(32))">
WEBHOOK_SECRET=<同上 token_hex(16)>
INTERNAL_API_KEY=<同上>

# 跨网关键：指 Bambuddy 的 Tailscale IP
BAMBUDDY_BASE_URL=http://<BAMBUDY_TS_IP>:8000/api/v1
BAMBUDDY_API_KEY=

MINIO_ENDPOINT=minio:9000          # compose 内服务名
MINIO_ACCESS_KEY=<改强随机>
MINIO_SECRET_KEY=<改强随机>
MINIO_BUCKET=bme-3dfarm-models
MINIO_SECURE=false
```

> compose 里 DB/Redis/MinIO 用服务名（`mysql`/`redis`/`minio`）是因为 backend 和它们在同一 compose 网络；但 Celery 任务里 Poller 调 Bambuddy 走的是公网/Tailscale，所以 `BAMBUDDY_BASE_URL` 必须是 Tailscale IP，不是服务名。

建表 + 种子费率（compose 起的 backend 首次会从模型建表；费率手动 seed 一次）：
```bash
docker compose exec backend python seed_pricing.py
```

### 3.5 Webhook 反向通（Bambuddy → 校园后端）
Webhook 是 Bambuddy **主动 POST** 到后端。开发机上的 Bambuddy 要能 reach 校园机的 5002——同样走 Tailscale。在 Bambuddy 配 Webhook 时 URL 用后端的 Tailscale IP：
```
http://<BACKEND_TS_IP>:5002/internal/webhooks/bambuddy/<WEBHOOK_SECRET>
```
（命令见 [真机接入与部署指南.md §6.3](真机接入与部署指南.md)，把 `127.0.0.1` 换成 `<BACKEND_TS_IP>`。）

> 即便 Webhook 因某原因不通，Celery Poller（每 30s 主动拉 Bambuddy）仍会兜底同步订单/打印机状态——这是系统本来就有的容错。所以跨网部署即使 Webhook 偶发不稳，也不会断。

### 3.6 前端：一个 nginx 反代收口
校园网常有**客户端隔离**（同 wifi 的手机互不可见），所以前端别让客户机直连 5002/MinIO。建议前端 build 后用 nginx 托管，并把 API 反代到后端：

```nginx
server {
    listen 80;
    server_name <校园机IP或域名>;

    # customer 前端
    location / { root /var/www/customer; try_files $uri /index.html; }
    # admin 前端（或另起一个 server / 端口）
    location /admin/ { alias /var/www/admin/; try_files $uri /admin/index.html; }
    # API 反代到后端容器（同机）
    location /api/ {
        proxy_pass http://127.0.0.1:5002/;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }
}
```
前端 `.env.production`：`VITE_API_BASE_URL=/api`（同源，无 CORS）。

> 这样客户/管理员手机只访问校园机的 80 端口，不碰 5002/3306/6379/9000——**校园网半信任环境下，只暴露前端这一个口**。

## 4. 校园网特有坑清单

| 坑 | 表现 | 对策 |
|---|---|---|
| **入站防火墙** | 校外/路由器侧连不到校园机的 5002 | 用 Tailscale（出站），别指望端口转发 |
| **客户端隔离** | 同校园 wifi 的手机连不到前端 / 互不可见 | 前端走 nginx 反代收口；或让访问端也接 Tailscale |
| **私有地址不可路由** | 校园机 ping 打印机 192.168.x.x 超时 | 正常现象，走 Bambuddy（它在内网） |
| **SSDP 发现失效** | Bambuddy 跨网自动发现不了打印机 | 手填打印机 IP（你已经这么做了） |
| **MTU/大包** | Tailscale 隧道偶尔大文件上传断 | MinIO 大模型文件上传若失败，开发机侧 Bambuddy/MinIO 别走隧道——只有后端↔Bambuddy 的控制流量走隧道，模型文件存在校园机本地 MinIO |
| **服务自启** | 校园机重启后栈没起 | `docker compose up -d` 已含 `restart` 策略；或 systemd unit |

## 5. 端到端验证（跨网部署后）

1. 校园机：`docker compose ps` 全部 Up；`curl http://127.0.0.1:5002/` → 200
2. 校园机：`curl http://<BAMBUDY_TS_IP>:8000/health` → 200（跨隧道通）
3. 校园机：`docker compose exec backend python -c "from bambuddy_adapter import BambuddyAdapter; print(BambuddyAdapter().list_printers())"` → 能列出真打印机
4. 开发机 Bambuddy：`curl http://<BACKEND_TS_IP>:5002/` → 200（反向通）
5. 浏览器开前端 → 走一遍 [真机接入指南 §10 端到端流程](真机接入与部署指南.md)
6. 真机下发 → Bambuddy 收到队列 → 打印机动 → Poller/Webhook 回传订单状态

任一步超时，先查 Tailscale 状态：`tailscale status`（两端应都是 `active`，能 ping 对方 100.x）。

## 6. 如果连 Tailscale 也用不了的兜底

- **frp**：需要一台公网 IP 的中转机。Bambuddy 侧起 frpc 把 8000 反向暴露到中转，校园机通过中转访问。Webhook 同理反向。比 Tailscale 多一台机器 + 配置。
- **校园 VPN**：如果学校有 VPN 能拨进打印机所在子网，校园机拨 VPN 后直接用 Bambuddy 内网地址（回到方案 A）。
- **全栈搬到打印机内网**：放弃校园机，找一台能常开的小主机接在路由器下跑全栈（= [真机接入指南](真机接入与部署指南.md) 原样）。最省心，但失去"部署到校园机"的初衷。

---

## 7. 安全要点（校园网是半信任网络）

- `JWT_SECRET` / `DB_PASSWORD` / `WEBHOOK_SECRET` / `INTERNAL_API_KEY` / MinIO 凭据**全部强随机**，不要用 dev 默认值。
- 只暴露前端的 80/443；5002/3306/6379/9000 只听 `127.0.0.1` 或 compose 内网，**不绑 0.0.0.0 到校园网卡**。
- Bambuddy 的 API 若有 key 能开就开（`BAMBUDDY_API_KEY`），别裸奔 8000。
- 定期 `docker compose pull && docker compose up -d` 更新镜像。
