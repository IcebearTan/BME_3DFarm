# 3D 打印农场 — 真机接入与部署指南

> 本指南让另一台电脑从零部署整个系统 + 接入真打印机，在打印机局域网内端到端测试。

---

## 0. 架构总览

```
部署机（局域网内一台电脑）
├── 后端 Flask 5002        ← Celery worker + beat（Poller 每 30s 同步打印机状态/订单进度）
├── MinIO 9000             ← 3D 模型文件存储
├── Bambuddy 8000          ← 打印机管理底座（Webhook 推 print 事件 → 后端）
│   └── 真打印机 ×N         ← 同局域网（MQTT/FTPS/RTSPS）
├── slicer-api 3003        ← 可选，服务器切片（OrcaSlicer headless）
├── MySQL 3306 + Redis 6379
├── customer 前端 5180     ← 客户端（注册/下单/额度/订单/打印机状态）
└── admin 前端 5181        ← 管理端（订单/报价/审核/下发/发额度/打印机监控/费率）
```

**数据流**：客户下单 → admin 审核/下发 → Bambuddy 队列 → 打印机自动打印 → Bambuddy Webhook 推完成 → 后端自动实扣 credit + 客户进度更新。全程管理员不切 Bambuddy UI。

---

## 1. 前置条件

### 硬件
- **部署机**：局域网内一台电脑（Windows / Mac / Linux 均可，建议 4 核 8GB+）
- **打印机**：Bambu Lab（P1S / A1 / X1 等），**与部署机同一局域网**
- **网络**：部署机能 ping 通打印机 IP

### 打印机准备（在打印机屏幕操作）
1. 设置 → 网络 → 记录**局域网 IP**（如 192.168.1.50）
2. 设置 → **开启 Developer Mode**（或 LAN Only 模式）
3. 设置 → **记录 Access Code**（4 位数字，打印机屏幕可查）
4. 记录**序列号 SN**（打印机背面贴纸 或 设置 → 关于）

### 软件（部署机安装）
- **Python 3.11+** + **uv**（包管理，`pip install uv` 或 `curl -LsSf https://astral.sh/uv/install.sh | sh`）
- **Node.js 18+**（前端 build）
- **Docker**（Bambuddy + MinIO + slicer-api）
- **MySQL 8**（端口 3306 或自定）+ **Redis**（6379）

## 4. 后端配置

### 4.1 编辑 `backend/.env`

```env
# MySQL（改为你部署机的配置）
DB_HOST=127.0.0.1
DB_PORT=3306
DB_NAME=bme_3dfarm
DB_USERNAME=root
DB_PASSWORD=你的MySQL密码

# Redis
REDIS_URL=redis://localhost:6379/0

# JWT（随机字符串，生产必改）
JWT_SECRET=用-python -c "import secrets; print(secrets.token_hex(32))"-生成

# Bambuddy（Docker 起后填这里）
BAMBUDDY_BASE_URL=http://127.0.0.1:8000/api/v1
BAMBUDDY_API_KEY=

# Webhook 鉴权（随机字符串，Bambuddy 配 Webhook 时用同一个）
WEBHOOK_SECRET=用-python -c "import secrets; print(secrets.token_hex(16))"-生成

# 内部 API Key（随机）
INTERNAL_API_KEY=同样随机生成

# MinIO
MINIO_ENDPOINT=127.0.0.1:9000
MINIO_ACCESS_KEY=minioadmin
MINIO_SECRET_KEY=minioadmin
MINIO_BUCKET=bme-3dfarm-models
MINIO_SECURE=false
```

### 4.2 装依赖 + 建表 + 种子费率

```bash
cd backend

# 建 venv + 装依赖（uv）
uv venv
uv pip install -r requirements.txt --python .venv/Scripts/python.exe    # Windows
# uv pip install -r requirements.txt --python .venv/bin/python          # Mac/Linux

# 建费率表 + 种子（base_fee/machine_hour_price/材料单价）
PYTHONIOENCODING=utf-8 .venv/Scripts/python.exe seed_pricing.py
```

### 4.3 启动后端

```bash
PYTHONIOENCODING=utf-8 .venv/Scripts/python.exe app.py
# 后端跑在 5002
```

验证：`curl http://127.0.0.1:5002/health` → `{"status":"ok"}`

## 6. Bambuddy + 接入真打印机

### 6.1 起 Bambuddy（Docker）

```bash
docker run -d --name bambuddy -p 8000:8000 \
  -v bambuddy_data:/app/data \
  --restart unless-stopped \
  ghcr.io/maziggy/bambuddy:latest
```

验证：`curl http://127.0.0.1:8000/health` → `{"status":"healthy"}`

> 如果 ghcr 拉不动，试 `docker.io/maziggy/bambuddy:latest`（Docker Hub 直连，国内可能需要代理）。

### 6.2 添加真打印机

浏览器打开 **http://localhost:8000** → 打印机页面 → 添加打印机：

- **IP**：打印机局域网 IP（第 1 步记录的）
- **Access Code**：打印机屏幕查到的
- **SN**：打印机序列号

添加后 Bambuddy 自动 MQTT 连接打印机。**打印机出现在 `printers/` 列表**（我们的 dispatch queue 能找到它，跟 Virtual Printer 不同）。

验证：
```bash
curl http://127.0.0.1:8000/api/v1/printers/
# 应返回你加的真打印机
```

### 6.3 配置 Webhook（关键：让 Bambuddy 推 print 事件到后端）

```bash
# 用你 .env 里的 WEBHOOK_SECRET 替换 <SECRET>
curl -X POST http://127.0.0.1:8000/api/v1/notifications/ \
  -H "Content-Type: application/json" \
  -d '{
    "name": "3DFarm Webhook",
    "provider_type": "webhook",
    "enabled": true,
    "config": {"url": "http://127.0.0.1:5002/internal/webhooks/bambuddy/<SECRET>"},
    "on_print_start": true,
    "on_print_complete": true,
    "on_print_failed": true,
    "on_print_stopped": true
  }'
```

> Bambuddy 推 print_start/complete/failed 时，后端自动更新订单状态 + 实扣/释放 credit。

### 6.4 （可选）配 Slicer API（全自动切片）

起 slicer-api sidecar：
```bash
docker run -d --name orca-slicer-api -p 3003:3000 \
  -v orca_slicer_data:/app/data \
  --restart unless-stopped \
  ghcr.io/maziggy/orca-slicer-api:latest
```

Bambuddy UI → **Settings → Slicer**：
- **Use Slicer API**：开
- **Sidecar URL**：`http://127.0.0.1:3003`
- **Preferred Slicer**：OrcaSlicer

> 还需导入 OrcaSlicer preset（printer/process/filament profile），否则 slice 会报 "printer preset required"。先跳过也没关系——客户传 `.gcode.3mf`（已切片）的路径不依赖 slicer-api。

## 7. Celery Worker + Beat（Poller 定时同步）

开两个终端（每个持续运行）：

```bash
cd backend

# 终端 1：Worker（执行 Poller/异步任务）
celery -A celery_app.celery worker --loglevel=info

# 终端 2：Beat（定时触发，每 30s 同步打印机 + 订单状态）
celery -A celery_app.celery beat --loglevel=info
```

> Poller 每 30s 调 Bambuddy 同步：打印机状态写入 `printer` 表（前端监控页读）+ 活跃订单进度更新。

## 10. 端到端验证流程

按顺序在浏览器操作：

| 步骤 | 角色 | 操作 | 预期 |
|---|---|---|---|
| 1 | admin | 发额度（搜索客户 → 发 credit） | 客户余额 + |
| 2 | customer | 下单（用 Bambu Studio 切片后上传 .gcode.3mf） | 自动报价（克重×单价+时长×机时+基础费） |
| 3 | customer | 确认下单 | 额度冻结 |
| 4 | admin | 审核通过（一键 3 步到 READY_TO_PRINT） | 订单排队中 |
| 5 | admin | 下发打印（填 Bambuddy printer_id） | 系统自动 upload archive + add_to_queue → 打印机开始 |
| 6 | 打印机 | 自动打印 | Bambuddy 推 print_started → 后端订单 PRINTING |
| 7 | customer | 看进度条 | Poller 更新 public_progress |
| 8 | 打印机 | 打印完成 | Bambuddy 推 print_complete → 后端自动实扣 credit |
| 9 | admin | 打印机监控页 | 真机状态（温度/进度/队列） |

## 11. 常见问题

### Docker Hub 拉不动（国内网络）
- Bambuddy / slicer-api 在 **ghcr.io**（GitHub Container Registry），通常国内可拉
- MinIO 在 Docker Hub，如拉不动换 `docker.m.daocloud.io/minio/minio`

### 后端改代码不生效（Flask 无 reload）
Flask 用 `app.run()`（无 debug），改代码后要重启。**杀干净再起**（Flask 子进程残留坑）：
```bash
# Windows
Get-NetTCPConnection -LocalPort 5002 -State Listen | ForEach-Object { Stop-Process -Id $_.OwningProcess -Force }
# Mac/Linux
lsof -ti:5002 | xargs kill -9
```

### dispatch 报 "Printer not found"
Virtual Printer 不在 `/printers/`（REST queue 只认真机）。**确保 Bambuddy 加了真打印机**（第 6.2 步），`curl http://127.0.0.1:8000/api/v1/printers/` 有真机。

### Webhook 没推 / 订单状态不更新
1. 检查 Bambuddy notification 配了（`GET http://127.0.0.1:8000/api/v1/notifications/`）
2. 检查后端 webhook 可达（`curl http://127.0.0.1:5002/internal/webhooks/bambuddy/<SECRET>`）
3. Celery worker + beat 在跑（Poller 兜底）

### 切片报 "printer preset required"
slicer-api 的 preset 未配（OrcaSlicer profile）。两个选择：
- **跳过全自动切片**：客户自己用 Bambu Studio 切完传 .gcode.3mf（已支持自动报价）
- **配 preset**：Bambuddy Settings → Slicer → 导入 OrcaSlicer profile（printer + filament + process）

### Windows 编码报错（UnicodeEncodeError）
设环境变量：`PYTHONIOENCODING=utf-8`（PowerShell: `$env:PYTHONIOENCODING="utf-8"`）

### 端口冲突
| 服务 | 默认端口 |
|---|---|
| 后端 | 5002 |
| customer 前端 | 5180 |
| admin 前端 | 5181 |
| Bambuddy | 8000 |
| MinIO | 9000 / 9001 |
| slicer-api | 3003 |
| Redis | 6379 |
| MySQL | 3306 |
