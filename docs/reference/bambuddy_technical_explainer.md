# Bambuddy 技术解析：它是如何与打印机通信的，你的系统如何与它通信

> 本文档面向团队成员解答以下问题：
> 1. Bambuddy 是什么类型的项目，它是如何工作的？
> 2. 搭建这套系统是否需要在打印机农场局域网内放一台主机？
> 3. Flask 后端是通过局域网还是公网与 Bambuddy 通信？
> 4. 打印机通信与 Web 应用前后端通信有什么异同？

---

## 1. Bambuddy 是什么

Bambuddy 是一个**自托管的 Bambu Lab 拓竹 3D 打印机管理系统**，用 Python (FastAPI) + React 写的一个 Web 应用。它的定位是"本地运行、不依赖云服务"的打印机管理中控。

简单理解：

```
你平时用 Bambu Studio 切片 → 通过 Bambu 云端/局域网发送给打印机

Bambuddy 的作用是：替代云端，直接在局域网内管理你的所有打印机
```

它能做的事包括：实时监控打印机状态、管理打印队列、归档打印历史、管理耗材库存、自动调度打印任务、推送通知（打印完成/失败）等。

### 1.1 Bambuddy 的角色定位

在你的客户服务平台中，Bambuddy 的角色是**内部工具**，不是客户直接用的东西：

```
客户 → 你的 Flask 业务系统 → Bambuddy → 打印机
(公网)    (你的服务器)        (局域网内)    (局域网内)
```

客户永远不直接接触 Bambuddy。

## 2. Bambuddy 如何与打印机通信

这是理解整个架构的关键。Bambuddy 与 Bambu Lab 打印机之间**不是 HTTP 通信**，而是使用了多个专用协议。

### 2.1 通信全景

```
┌─────────────┐     MQTT (8883)      ┌──────────────┐
│             │ ◄──────────────────► │              │
│             │     状态/命令          │              │
│   Bambuddy  │                      │   打印机      │
│   服务器     │     FTPS (990)       │  (如 P1S)    │
│             │ ◄──────────────────► │              │
│             │     文件传输          │              │
│             │                      │              │
│             │     RTSPS (322)      │              │
│             │ ◄──────────────────► │              │
│             │     摄像头视频流       │              │
└─────────────┘                      └──────────────┘
```

### 2.2 三个核心协议

#### (1) MQTT — 实时状态和命令控制

| 项目 | 说明 |
|---|---|
| 端口 | 8883 |
| 加密 | TLS（打印机使用自签名证书） |
| 认证 | 用户名 `bblp`，密码是打印机的 Access Code |
| 用途 | 接收打印机状态推送（温度、进度、AMS、错误），发送控制命令（开始打印、暂停、速度调节） |
| 通信模式 | Bambuddy 订阅 `device/{序列号}/report`，向 `device/{序列号}/request` 发布命令 |
| 特点 | 每台打印机内部运行了自己的 MQTT Broker，Bambuddy 是作为客户端连接到打印机 |

```
工作方式（不是请求-响应，而是发布-订阅）：

打印机  ──publish──►  topic: device/01S00C12345/report  ──►  Bambuddy 订阅并接收
  (实时推送状态：温度45°、进度23%、剩余2小时...)

Bambuddy ──publish──►  topic: device/01S00C12345/request  ──►  打印机 接收并执行
  (发送命令：暂停、恢复、设置速度...)
```

#### (2) FTPS — 文件传输

| 项目 | 说明 |
|---|---|
| 端口 | 990（隐式 TLS） |
| 加密 | TLS 控制通道加密，数据通道根据打印机型号有所不同 |
| 认证 | 用户名 `bblp`，密码是打印机的 Access Code |
| 用途 | 上传 3MF 打印文件到打印机 SD 卡，下载打印记录、延时摄影等 |
| 特点 | 使用被动模式（PASV），打印机作为 FTP 服务器 |

```
工作方式：

Bambuddy ──FTP连接──► 打印机IP:990
  ├── 上传: STOR /model/ORD-xxx__PLA-WHITE.gcode.3mf  (把切片好的文件发到打印机)
  └── 下载: RETR /timelapse/xxx.mp4  (下载延时摄影)
```

#### (3) RTSPS — 摄像头视频流

| 项目 | 说明 |
|---|---|
| 端口 | 322（部分型号）或 6000（A1/P1 系列） |
| 加密 | TLS |
| 认证 | Access Code 嵌入 URL |
| 用途 | 实时摄像头画面流 |
| URL 格式 | `rtsps://bblp:{access_code}@{ip}:322/streaming/live/1` |

### 2.3 打印机发现

Bambuddy 使用 **SSDP 协议**（局域网设备发现）来扫描网内的 Bambu Lab 打印机：

- 组播地址：`239.255.255.250`，端口 `2021`
- 每 3 秒发送一次搜索请求
- 打印机回复自己的序列号、名称、型号
- 在 Docker 中（无法使用组播），改用子网扫描：逐 IP 探测 990 和 8883 端口

### 2.4 连接打印机需要什么

每台打印机在 Bambuddy 中存储了三个关键信息：

```
IP 地址:     192.168.1.100     ← 打印机在局域网中的 IP
序列号:      01S00C123456789   ← 打印机唯一标识，用于 MQTT topic
Access Code: 12345678          ← 打印机屏幕上设置的访问码，用于所有协议的认证
```

**这三个信息决定了 Bambuddy 必须能通过网络到达打印机的 IP。**

## 3. 网络架构：你需要在打印机旁边放一台主机吗？

### 3.1 答案：是的，需要一台主机在局域网内

原因是：**Bambu Lab 打印机的所有通信协议都是局域网协议，不支持从公网直接访问。**

```
为什么不能把 Bambuddy 放在云服务器上：

云服务器 (公网 IP)  ──×──►  打印机 (局域网 IP 192.168.1.100)
                         ↑
                    打印机没有公网 IP
                    打印机不接受来自公网的连接
                    MQTT/FTP/RTSP 都需要直接网络可达
```

### 3.2 推荐网络拓扑

```
┌─────────────── 打印机农场局域网 ──────────────┐
│                                                │
│  ┌──────────┐  ┌──────────┐  ┌──────────┐     │
│  │ Printer01│  │ Printer02│  │ Printer03│     │
│  │ P1S      │  │ X1C      │  │ A1 Mini  │     │
│  │192.168.1.10│ │192.168.1.11│ │192.168.1.12│  │
│  └────┬─────┘  └────┬─────┘  └────┬─────┘     │
│       │              │              │           │
│       └──────────────┼──────────────┘           │
│                      │  局域网交换机             │
│              ┌───────┴────────┐                 │
│              │   主机服务器     │                │
│              │                │                 │
│              │  Bambuddy      │  ← 管理打印机    │
│              │  (Docker)      │                 │
│              │  Flask 后端     │  ← 你的业务系统  │
│              │  MySQL         │                 │
│              │  Redis         │                 │
│              │  Celery Worker │                 │
│              └───────┬────────┘                 │
│                      │                          │
└──────────────────────┼──────────────────────────┘
                       │
                  路由器/防火墙
                       │
              ┌────────┴────────┐
              │    公网 (互联网)   │
              └────────┬────────┘
                       │
              ┌────────┴────────┐
              │   客户浏览器      │
              │   管理员浏览器    │
              └─────────────────┘
```

### 3.3 为什么 Flask 后端也要在同一局域网

你的 Flask 后端通过 HTTP REST API 调用 Bambuddy：

```
Flask 后端  ──HTTP GET──►  Bambuddy:8000/api/v1/printers
Flask 后端  ──HTTP POST──► Bambuddy:8000/api/v1/queue
```

这个 HTTP 调用走的是**局域网内网通信**，不经过公网：

```
Flask 后端 (192.168.1.100) ──局域网──► Bambuddy (192.168.1.100:8000)
                                      或同一台机器上的 Docker 容器
```

**好处：**
- 延迟极低（< 1ms）
- 带宽不受公网限制
- 安全，不暴露 Bambuddy API 到公网
- 不消耗公网流量

### 3.4 最小部署方案：一台主机搞定一切

对于小规模（10 台打印机以内），可以用**一台主机**运行所有东西：

```
一台 Linux 服务器（如 Intel NUC / 迷你主机）
├── Docker Compose
│   ├── Bambuddy 容器      (host 网络模式, 端口 8000)
│   ├── Flask 后端容器      (host 网络模式, 端口 5000)
│   ├── MySQL 容器          (仅内网访问)
│   ├── Redis 容器          (仅内网访问)
│   └── Celery Worker 容器  (后台任务)
│
├── 连接到局域网交换机
│   └── 交换机连接所有打印机
│
└── 通过路由器端口转发或反向代理暴露 443 端口给公网
    └── 客户通过 HTTPS 访问 Flask 后端
```

### 3.5 远程管理（如果管理员不在局域网内）

如果管理员需要从外部查看 Bambuddy 管理面板，不要直接暴露 Bambuddy 到公网。使用：

- **Tailscale / ZeroTier / WireGuard**：组建虚拟局域网，安全访问内网服务
- **VPN**：远程拨入局域网

## 4. 打印机通信 vs Web 应用前后端通信的对比

这是最容易混淆的部分。下面用表格和图示说明异同。

### 4.1 对比总览

| 维度 | Web 前后端通信 | Bambuddy ↔ 打印机通信 | Flask ↔ Bambuddy 通信 |
|---|---|---|---|
| **协议** | HTTP/HTTPS | MQTT + FTPS + RTSPS | HTTP/HTTPS |
| **模式** | 请求-响应（客户端发起） | 发布-订阅 + 文件传输 + 流媒体 | 请求-响应 |
| **连接方向** | 浏览器 → 服务器 | Bambuddy → 打印机（Bambuddy 是客户端） | Flask → Bambuddy（Flask 是客户端） |
| **谁监听** | 服务器监听端口，等待连接 | **打印机**监听端口（8883/990/322） | Bambuddy 监听 8000 |
| **谁发起** | 浏览器（前端）发起请求 | Bambuddy 发起连接到打印机 | Flask 发起请求到 Bambuddy |
| **实时性** | 轮询或 WebSocket 推送 | MQTT 持久连接，实时推送 | 普通 HTTP，无实时 |
| **数据格式** | JSON | JSON（MQTT payload）、二进制（文件/视频） | JSON |
| **网络** | 公网（互联网） | 局域网 | 局域网 |
| **认证** | JWT / Cookie / API Key | Access Code（设备密码） | API Key（X-API-Key 请求头） |

### 4.2 核心区别：谁是"服务器"

在 Web 应用中：
```
浏览器（客户端）──请求──► 服务器（监听端口，等待请求）
```

在打印机通信中，角色**反转了**：
```
Bambuddy（客户端）──连接──► 打印机（监听端口 8883/990/322）
                           ↑ 打印机才是"服务器"！
```

打印机内部运行了 MQTT Broker、FTP Server、RTSP Server。Bambuddy 是主动连接打印机的客户端。

### 4.3 核心区别：通信模式

**Web 前后端：请求-响应**

```
浏览器: "给我订单列表"  ──►  服务器: 处理请求
服务器: 返回订单列表     ──►  浏览器: 显示

特点：客户端问一句，服务器答一句。不问不答。
```

**Bambuddy ↔ 打印机：发布-订阅（MQTT）**

```
打印机: "我当前温度220°，进度45%"  ──►  Bambuddy: 收到，更新数据库
打印机: "我当前温度221°，进度46%"  ──►  Bambuddy: 收到，更新数据库
打印机: "打印完成！"                ──►  Bambuddy: 收到，触发通知
Bambuddy: "请暂停打印"              ──►  打印机: 执行暂停

特点：打印机持续主动推送状态，Bambuddy 持续监听。不需要 Bambuddy 去问。
```

这就是为什么 Bambuddy 需要与打印机保持持久的 MQTT 连接 — 状态是打印机主动推送的，不是轮询来的。

### 4.4 你的系统中的三种通信关系

```
┌─────────────────────────────────────────────────────┐
│                                                     │
│  ① 客户浏览器 ←──HTTP/HTTPS──→ Flask 后端           │
│     (公网)        请求-响应         (局域网)          │
│                                                     │
│  ② Flask 后端  ←──HTTP───────→ Bambuddy              │
│     (局域网)     请求-响应        (局域网)            │
│     通过 Celery Worker 定时调用                      │
│                                                     │
│  ③ Bambuddy    ←──MQTT/FTPS──→ 打印机                │
│     (局域网)     发布-订阅/文件传输  (局域网)          │
│     持久连接，打印机主动推送状态                       │
│                                                     │
└─────────────────────────────────────────────────────┘

① 和 ② 都是 HTTP，但 ① 走公网，② 走局域网
② 和 ③ 都在局域网，但 ② 是 HTTP，③ 是 MQTT/FTPS
```

### 4.5 你的 Flask 后端如何获取打印机状态

Flask 后端**不直接连接打印机**，而是通过两种方式从 Bambuddy 获取状态：

**方式一：主动轮询（Poller Worker）**

```
Celery Worker (每30秒)
  └── HTTP GET http://bambuddy:8000/api/v1/printers/{id}/status
      └── Bambuddy 从自己的 MQTT 连接中读取最新状态返回
          └── 这个状态是打印机通过 MQTT 实时推送过来的
```

**方式二：Webhook 接收（事件推送）**

```
打印机 ──MQTT推送──► Bambuddy ──Webhook──► Flask 的 webhook 接收器
("打印完成")        (收到事件)     (HTTP POST)
                                   └── 更新订单状态、触发扣费
```

注意这里有一个有趣的"协议转换"链：

```
打印机的 MQTT 事件 → Bambuddy 接收 → Bambuddy 通过 HTTP Webhook 推送给你的 Flask → Flask 处理

打印机协议 (MQTT) → 中间层转换 → 你的系统协议 (HTTP)
```

这就是 Bambuddy 作为"桥接层"的核心价值 — 它把打印机的专用协议（MQTT/FTPS/RTSPS）转换成了你系统可以使用的标准 HTTP REST API。

## 5. 完整的数据流示例

以"客户下单打印一个模型"为例，展示完整的数据流动：

```
第 1 步：客户下单
客户浏览器 ──HTTPS POST──► Flask 后端 (公网 → 局域网)
  "我要打印这个 STL 文件，PLA 白色"
  └── 创建订单，保存文件到 uploads/models/

第 2 步：管理员审核
管理员浏览器 ──HTTPS POST──► Flask 后端
  "审核通过，报价 32 点额度"
  └── 创建报价，等待客户确认

第 3 步：客户确认
客户浏览器 ──HTTPS POST──► Flask 后端
  "确认下单"
  └── 冻结 32 点额度

第 4 步：管理员下发打印（半自动）
管理员浏览器 ──HTTPS POST──► Flask 后端
  "分配到 Printer-03"
  └── Flask 通过 Celery Worker 调用:
      Flask Worker ──HTTP POST──► Bambuddy:8000/api/v1/queue
        "把这个文件加入 Printer-03 的队列"
        └── Bambuddy 通过 FTP 把文件上传到打印机
            Bambuddy ──FTPS STOR──► 打印机 (192.168.1.12:990)

第 5 步：打印机开始打印，实时推送状态
打印机 ──MQTT publish──► Bambuddy
  "打印开始了，进度 0%"
  └── Bambuddy 收到 MQTT 消息

第 6 步：Bambuddy 推送事件给你的系统
Bambuddy ──HTTP Webhook──► Flask 后端
  {"event": "print_started", "printer_id": 3, ...}
  └── 更新订单状态为 PRINTING

第 7 步：Poller 兜底同步（每 30 秒）
Celery Worker ──HTTP GET──► Bambuddy:8000/api/v1/printers/3/status
  └── Bambuddy 返回最新状态（来自 MQTT 推送）
      └── 更新订单进度到 45%

第 8 步：打印完成
打印机 ──MQTT publish──► Bambuddy ──Webhook──► Flask
  "打印完成，实际用料 28g，用时 2.5 小时"
  └── 订单状态 → PRINT_COMPLETED → QC_PENDING

第 9 步：质检通过，实扣额度
管理员 ──HTTPS POST──► Flask
  "质检通过"
  └── 冻结的 32 点额度转为实扣（或按实际用量调整）

第 10 步：通知客户
Flask ──邮件/通知──► 客户
  "您的订单已完成，可以取件了"
```

## 6. 硬件和网络需求总结

### 必须有的

| 设备 | 说明 |
|---|---|
| 一台服务器主机 | 放在打印机农场局域网内，运行 Bambuddy + Flask + MySQL + Redis |
| 局域网交换机 | 连接所有打印机和服务器 |
| 路由器 | 提供公网出口，用于客户 HTTPS 访问 Flask 后端 |

### 服务器配置建议

| 规模 | CPU | 内存 | 存储 | 说明 |
|---|---|---|---|---|
| 1-5 台打印机 | 2 核 | 4 GB | 100 GB SSD | Intel NUC 或迷你主机即可 |
| 5-20 台打印机 | 4 核 | 8 GB | 500 GB SSD | 需要较多存储存放 3D 模型文件 |
| 20+ 台打印机 | 4-8 核 | 16 GB | 1 TB SSD | 考虑分离 Bambuddy 和业务服务器 |

### 网络要求

- 打印机和服务器在同一局域网（同一子网）
- 服务器有稳定网络连接到公网（用于客户访问）
- 打印机不需要公网连接
- Bambuddy 使用 Docker `host` 网络模式运行
