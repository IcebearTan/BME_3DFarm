## 一、Mac 实地测试（Bambuddy + 打印机）

Phase 0 实地验证硬件链路，**只需要起 Bambuddy**，不需要 BME_3DFarm backend / MySQL / Redis。

### 前置检查

- [ ] Mac 已装 Docker Desktop 并**启动**（菜单栏鲸鱼图标常亮）
- [ ] Mac 与打印机**同一局域网**（同一 Wi-Fi / 网线）
- [ ] 打印机已开 **LAN Mode + Developer Mode**
- [ ] 手头有打印机的 **IP / 序列号 / Access Code**（BambuPrinterGateway 已验证过这套凭据可用）
- [ ] 已 `git clone` 本仓库到 Mac

### 步骤

**1. 只起 Bambuddy**

```bash
cd BME_3DFarm
docker compose up -d bambuddy
```

首次会拉镜像（~200MB+），等几分钟。完成后 `docker ps` 应看到 `bambuddy` 状态 `healthy`。

**2. 浏览器开 http://localhost:8000**

- 首次会要求 **setup**：创建管理员账户 + 设密码

**3. Add Printer 加那台 P1S**

- 手动填 **IP / 序列号 / Access Code**
- ⚠️ Mac 的 Docker Desktop **不支持 host 网络模式**，SSDP 自动发现**不工作** → 必须选"手动输入 IP"，不要等自动扫描

**4. 验证连接**

Bambuddy 能读到打印机实时状态：温度、`gcode_state`、AMS 槽位。有 AMS 的话顺便确认槽位识别（用于回来填 `has_ams`）。

**5. 端到端打印测试**

上传一个小的 `.gcode.3mf` → 启动打印 → 确认 **开始 → 进度推进 → 完成** 全链路。这验证"局域网 IP+SN+授权码 → MQTT/FTPS → 真实打印"打通。

## 二、Bambuddy 配置（为 BME_3DFarm 接入做准备）

实地测通后，在 Bambuddy 做这两件事，BME_3DFarm 才能通过 API 接它：

1. **启用 auth**：Settings → Authentication → Enable
2. **建只读 API Key**：Settings → API Keys → New，权限选 **Read Status**（最小权限），复制 Key
3. **确认版本 ≥ 0.2.4.5**（Settings 里看；更早版本 API Key 权限模型不可靠）
4. 把 Key 填进 `backend/.env`：
   ```
   BAMBUDDY_API_KEY=你复制的key
   ```

## 三、BME_3DFarm backend 启动（回到开发机后）

### 本机开发（Windows，venv）

```bash
cd backend
python -m venv .venv
.venv/Scripts/python.exe -m pip install -r requirements.txt   # 或用 uv 见下
copy .env_example .env          # 填 MySQL/Redis/Bambuddy
flask db upgrade                # 建表（迁移脚本已 commit，无需 init/migrate）
python app.py                   # 监听 :5002
```

> **推荐用 uv**（快得多）：`uv venv .venv && uv pip install -r requirements.txt --python .venv/Scripts/python.exe`

### Docker 全栈（部署 / Mac 完整测试）

```bash
cp backend/.env_example backend/.env
# ⚠️ docker 模式 .env 要改这几项（容器间用服务名通信，不是 127.0.0.1）：
#   DB_HOST=mysql
#   DB_PORT=3306
#   DB_PASSWORD=root                 # 要和 mysql 容器一致（compose 默认 root）
#   REDIS_URL=redis://redis:6379/0
#   MINIO_ENDPOINT=minio:9000
#   BAMBUDDY_BASE_URL=http://bambuddy:8000/api/v1
docker compose up -d
docker compose exec backend flask db upgrade    # 首次建表
```

### Celery（Phase 2+ 用，骨架已就绪）

```bash
celery -A celery_app.celery worker --loglevel=info
celery -A celery_app.celery beat --loglevel=info
```

### 录入打印机

编辑 `backend/printers.yaml`（填 `bambuddy_printer_id` + `has_ams` + `enabled`），然后：

```bash
python scripts/sync_printers.py    # 幂等，按 public_name upsert
```

## 六、故障排查

| 现象 | 排查 |
|---|---|
| Bambuddy 连不上打印机 | IP 是否对 / Mac 与打印机是否同局域网 / 打印机 LAN Mode + Developer Mode 是否开 / Access Code 是否正确 |
| Mac 自动发现不到打印机 | 正常（Docker for Mac 无 host 网络），手动填 IP |
| 端口冲突 | Bambuddy 占 8000，backend 占 5002，确保没被占 |
| backend（docker）连不上 MySQL | `.env` 的 `DB_HOST` 要是 `mysql`（服务名），不是 127.0.0.1 |
| `flask db upgrade` 报错 | 确认 MySQL 已起、`.env` 的 DB_PASSWORD 与 mysql 容器一致（默认 root） |
| 容器里 backend 找不到 .env | compose 已用 `env_file: ./backend/.env` 注入，确认文件存在 |
| requirements.txt 装失败（gbk 解码错） | requirements.txt 注释必须 ASCII（中文注释会触发 Windows gbk 解码错） |
